# Простой пример авторизации с использованием Slim 4

Это **учебный пример веб-приложения на PHP**, демонстрирующий базовую авторизацию пользователей с использованием фреймворка **Slim 4** и механизма сессий.

## Основная функциональность

Приложение реализует простой flow аутентификации:

### 1. **Страница входа** (`GET /`)
- Отображает HTML-форму с полями для ввода имени пользователя и пароля
- Форма отправляет данные методом POST на `/login`

### 2. **Обработка входа** (`POST /login`)
- Принимает учетные данные из формы
- Проверяет их по списку пользователей с хешированными паролями:
  - `alice` : `pass123` (хранится в виде хеша)
  - `bob` : `secret123` (хранится в виде хеша)
- Использует `password_verify()` для безопасной проверки паролей
- При успешной аутентификации:
  - Сохраняет имя пользователя в сессии PHP (`$_SESSION['user']`)
  - Регенерирует session ID для защиты от session fixation атак
  - Перенаправляет на `/profile`
- При неудачной попытке возвращает ошибку 401

### 3. **Защищенная страница профиля** (`GET /profile`)
- Доступна только авторизованным пользователям
- Защищена middleware `$authMw`, который:
  - Проверяет наличие пользователя в сессии
  - Если пользователь не авторизован — перенаправляет на главную страницу
  - Если авторизован — пропускает запрос дальше
- Отображает данные пользователя:
  - Имя пользователя
  - Email адрес
  - Баланс счета (в рублях)
  - Кнопку выхода

### 4. **Выход** (`POST /logout`)
- Полностью очищает данные сессии (`$_SESSION = []`)
- Уничтожает сессию (`session_destroy()`)
- Перенаправляет на главную страницу

## Технологии

- **Slim 4** — микрофреймворк для маршрутизации HTTP-запросов
- **PSR-7** — стандартные HTTP-объекты (Request/Response)
- **PHP Sessions** — для хранения состояния авторизации между запросами
- **Docker** — для развертывания (nginx + PHP-FPM)

## Установка

### Создать проект Slim:

```bash
docker compose up -d --build
docker exec -it --user www-data nginx-phpfpm bash
composer require slim/slim:"4.*" slim/psr7
```

## Назначение

Это демонстрационный проект для изучения:
- Работы с Slim Framework
- Концепции middleware (промежуточного ПО)
- Базовой аутентификации через сессии
- Перенаправлений и защиты маршрутов

## Реализованные меры безопасности

- ✅ **Хеширование паролей** — используется `password_hash()` и `password_verify()`
- ✅ **Регенерация Session ID** — защита от session fixation атак
- ✅ **Полная очистка сессии** — при выходе удаляются все данные

## Ограничения (учебный проект)

**⚠️ Важно**: Это учебный пример, не предназначенный для production:
- Отсутствует защита от CSRF атак
- Нет rate limiting для предотвращения brute-force
- Пользователи хранятся в коде, а не в базе данных
- Отсутствует валидация входных данных
- Нет HTTPS (используется HTTP)
- Отсутствует логирование попыток входа
